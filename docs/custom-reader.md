# FlowReview：按功能链阅读本地代码变更

新用户从 [完整安装与使用指南](getting-started.md) 开始；本文说明阅读器参数与实现细节。

FlowReview 基于 [yadiff](https://github.com/baggiiiie/yadiff)，保留原来的 Git/jj/PR 用法，并新增独立的本地功能链阅读入口。

## 安装一次

在本仓库运行：

```powershell
npm ci
npm run build
```

也可双击 `setup-review.cmd`。构建后的全部脚本、语法高亮和主题都从本地加载；正常阅读不运行 npm、不使用 CDN、不请求 AI。源码升级后重新执行安装及构建。

## 生成并阅读

```powershell
node bin/flowreview.js --review D:\workspace2\docs\feature\review\review.json
```

Windows 可以把 review.json 拖到 `open-review.cmd`。报告必须提供 repositories（项目名、Git 根目录、比较模式），支持现有 code-change-review 的 JSON；工作区模式覆盖暂存、未暂存和未跟踪文件，忽略 Git ignore 文件。

原有命令也增加了转入口：`node bin/yadiff.js --review <review.json>`。

默认在输入报告旁的 `reader-snapshots/<时间>/` 创建独立快照。可用 `--out <新目录>` 指定位置；已有目录不会被覆盖。

```powershell
# 仅生成源码数据，不启动浏览器
node bin/flowreview.js --review review.json --out D:\reports\task-20261016 --build-only
# 再次打开已有快照，不重新访问业务仓库
node bin/flowreview.js --snapshot D:\reports\task-20261016
# 前台运行或仅打印地址
node bin/flowreview.js --snapshot D:\reports\task-20261016 --foreground --no-open
# 停止本工具的共享服务
node bin/flowreview.js --stop
```

本地服务只监听 127.0.0.1。已有服务会复用，可同时注册多份快照。默认端口 5188 被占用时自动选择空闲端口；不会终止其他进程。没有页面请求或心跳五分钟后退出，也可点击“停止本地服务”。浏览器被系统长期冻结后可能需要重新运行启动器。

运行信息默认保存在 `%USERPROFILE%\.yadiff-review`，阅读进度按源码和报告指纹独立保存，不写业务代码。可通过 `FLOWREVIEW_RUNTIME` 更改位置，兼容 `YADIFF_REVIEW_RUNTIME`。

## 阅读方式

- 默认从功能链进入，按报告整理的关联路径连续阅读；普通原有节点收起，可点路径按钮展开。
- 每处变化旁显示修改原因；原作用、行为变化、依据、待确认事项和验证记录可展开。
- 支持方法改动、完整方法、完整文件，前后对比、左右对照、修改前和修改后源码。
- 点击代码标识符，就地查看当前快照中已收集的同名定义；多个候选会列出类、签名和项目。可进入完整文件后返回。
- “看过”和“有疑问”互不排斥，疑问可写备注并集中回顾。备注失焦时保存，保存失败会提示。
- 文件目录保留全部实际变化。未关联到报告的文件有明确提示，不因功能链整理而漏掉。

## 证据边界

代码始终来自固定的本地/Git 采集结果，输入 JSON 自带的 code 不作为源码。Java 方法、字段和类的范围由 java-parser 提取；重载按签名区分，同一真实方法的多个说明会合并。解析失败保留完整源码并提示。

阅读顺序是报告作者整理的路径，不自动宣称相邻节点是直接调用。方法跳转当前按已收集文件的定义名称提供候选，未做完整 Java 类型解析，也不自动确认 Spring 注入、Feign、MQ 或反射的执行关系。库或未采集文件中的定义会明确提示没有匹配；不能据此认定不存在。

说明、必要性判断和测试结果来自输入报告；渲染器不认证这些结论。缺少原始版本证据时保留提醒。完整文件使用真实行号；只读源码片段会明确标注实际行范围与片段内行号。

快照包含源代码，按原项目的访问范围保管。服务接口仅访问已注册快照的文件 ID，不提供任意本地文件读取或业务代码修改接口。


测试只在临时目录创建和清理隔离 Git 仓库，并测试本机 HTTP API。可设置 REVIEW_TEST_TMP 指定测试目录。


### 完整业务流程与变更叠加

新报告的 flowPoint.journey 保存来源、输入输出、范围、业务步骤和过程边，implementationIds 引用本功能点的 hop.id。默认显示业务流程：保留未改主干，按阶段/项目分组，以颜色标出变化，概览提供第一处变化与传播步骤。点击步骤在右侧查看输入输出、处理分支、涉及表/下游、前后变化和实现方法，源码按需加载；来源详情在侧栏打开后自动收起。方法调用图可切换查看。没有 journey 的旧报告继续使用方法视图，不自动声称已覆盖完整业务。

业务状态由经源码核实的步骤说明提供，与 Git 方法变更独立。新方法可能只是实现抽取；业务图用 implementation 标明实现调整。异步任务须补齐持久化、调度/消费者及状态与结果反馈，范围和未验证内容如实记录。schema 字段见 code-change-review/references/report-format.md。

### 方法时序视图

方法总框通过 React Flow 画布展示，由 ELK 按已采集关系、项目归属及实际尺寸自动布局。框头打开完整方法源码；框内列出用途、变化原因、已有过程/分支及报告提供的调用关系，调用按钮打开目标方法。原有业务图可切换查看。不存在前后调用证据时，仅标目标方法新增，不推断调用边新增；不虚构返回值或运行时顺序。

对象挂接使用快照内方法范围的类型名词法出现位置，仅匹配无歧义的同项目对象；标明本链首次同名出现，不声称语义绑定或运行时首次使用。同名歧义、未定位对象单列。旧报告中的类、字段和上下文保留独立目录，缺方法定位时不自动补造内部时序。图中顺序不表示耗时，也不保证完整执行顺序。

方法总框使用整体状态边框和独立标题底色；对象变更移到方法外的对象列，通过引用虚线连接。对象支持新增/修改/删除，无法确定首次使用的仍单列。process 字符串可用 →、->、；或换行分步骤，成对【】表达嵌套循环/分支块；不配对时保留原文字，不猜步骤。方法执行流程始终可见，原有方法的详细分支可展开。流程中的已记录目标方法可点击进入完整源码。

### 流程画布

方法/对象框按已采集关系自动布置，并按实际高度避让。空白拖动平移，框角可拖动节点，支持缩放、适应全图、聚焦主方法和专注画布；自动排列恢复布局。流程内已明确出现的方法引用直接连到外部框，不再在底部重复调用列表。同名歧义或没有匹配步骤的关系仍保留待核对入口。位置调整仅在当前阅读状态中保留，刷新后恢复自动布局；布局不表达耗时或调用次数。


### React Flow + ELK（3.2.0）

方法画布使用 @xyflow/react 12.12.0（MIT）及 elkjs 0.12.0（选择 EPL-2.0）。许可证原文位于 licenses/，来源与声明见 THIRD-PARTY-LICENSES。ELK 在本地延迟加载，依赖随阅读器构建，不依赖 CDN。

SequenceView.tsx 使用库的节点、端口、视口与交互；lib/review/elk-layout.js 将实际尺寸、流程端口及关系映射到 ELK，返回节点位置和正交路径。拖动或节点尺寸变化后，缓存路径失效，由 React Flow 更新连线；自动排列重新计算避让。现有 JSON、manifest、源码快照与侧栏协议不变。布局不是运行时调用证据。
