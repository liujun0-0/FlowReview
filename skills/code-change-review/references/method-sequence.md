# 方法框与框内调用：采集要求

## 三层信息分别保存

`journey` 说明完整业务骨架、来源及结果；`chains.hops` 定位真实方法和对象；`chain.links` 说明方法间已核对的关系。业务步骤可对应多个方法，但不能用类级节点替代这些方法。修改方法以 `process` 表达局部顺序，以 `branches` 解释条件/异常，以 `behavior/why` 说明变化和原因。

先确定入口到结果的主路径，再补与改动合理性有关的未改步骤、分支、失败出口。逐个核对关键方法声明/体内的真实行号；同类辅助方法也须单独定位。若静态解析失败、生成代码或动态派发使方法无法定位，保留未知项及其具体影响，不能把类声明坐标冒充方法。

## 使用现有格式的局部示例

以下只是字段搭配，不是可以直接运行的项目报告。路径、行号、方法和证据必须换成真实值；完整报告仍须满足 report-format.md 的其他必填字段。

```json
{
  "hops": [
    {
      "id": "create", "project": "api", "file": "src/TemplateService.java",
      "line": 42, "func": "createFromSample", "side": "new", "type": "改实现",
      "role": "从已发布样例创建模板",
      "process": "1.校验操作人；2.新增调用 SampleClient.getPublished(id)，失败即终止；3.调用 Assembler.fromSample(sample, req) 构造 CreateDTO；4.调用 Core.create(dto)，成功后返回编号",
      "branches": ["样例未发布：不构造或保存模板", "Core 保存失败：向上返回错误，不返回成功编号"],
      "behavior": "由直接使用客户端正文改为读取服务端样例；新增 getPublished 调用，并在 DTO 中传播样例编号和版本",
      "why": "避免使用未发布内容，并保留创建来源"
    },
    {
      "id": "published", "project": "core", "file": "src/SampleQuery.java",
      "line": 70, "func": "getPublished", "side": "new", "type": "穿越未改",
      "role": "返回已发布样例的正文和版本",
      "process": "读取样例，检查发布状态，返回数据或失败"
    }
  ],
  "links": [{"from":"create","to":"published","label":"新增 Feign 调用：取已发布样例","confidence":"确定","evidence":"调用方 TemplateService.java:45；Feign path 与服务端映射、请求参数已分别核对；基准版本无该调用"}]
}
```

新增调用必须在调用方总框的 process/behavior 中写出方法名称，也用 links 指向目标 hop。目标方法可以未修改；不要为了表现新增调用而把其 type 改成新增。没有基准侧证据时只写调用事实和未知项，不判调用边新增。

## 对象与首次使用

对象 hop 用真实类/字段位置定位，role 说明生产者/消费者，behavior 说明变化字段及兼容影响，evidence 说明本链首次构造、读取、映射或传参的位置。对应使用方法也必须采集，并在其 process 中提到对象和用途。一个对象多次使用仍保持单份源码，不重复长说明。

当前工具只在同项目方法范围的词法标识符中寻找无歧义同名类型，以报告阅读顺序选择首次位置；可能匹配到声明或静态引用。这不是运行时首次使用，也不是语义类型绑定。跨项目契约、同名类型或未采集方法中的使用可能单列。不要编写工具未支持的 objectRefs、firstUse、calls、sequenceSteps 字段来暗示功能已实现。

## 快照交付前核对

生成固定快照后执行本 skill 的 `scripts/check_sequence.py <快照目录>/manifest.json --strict`。它按本地 manifest 检查方法定位和说明缺口，仅输出摘要/局部问题，不需要把所有源码输入模型。检查通过不证明关系或业务解释正确；警告、覆盖缺口和外部边界仍须核对。

对能够定位的方法，修正原 JSON 的 file/line/func/side 后重新生成新快照，不能修改旧 manifest 来掩盖问题。新报告的关键方法若未定位，标部分交付并解释缺口。仅转换已有报告时保留原结论及警告，未经核对不能把补充分析当作既有结论。


## 框内执行步骤与嵌套（3.1.1）

`process` 仍是字符串，阅读器按显式分隔符展示编号步骤。推荐 `获取锁 → 读取语言字典Map → for 每种语言【do 分页循环【fetchPage(language, cursor, pageSize) → 响应校验 → for 每条记录【必要字段校验 → 过滤 → 构造实体】 → 页内短事务写入 → 推进游标】】 → 全轮成功后差集删除 → 返回统计 → finally 释放锁`。

上述只是表达格式，不是所有同步方法的固定逻辑。按实际源码填写；lock 获取失败、跳过当前循环、异常、部分提交与 finally 应分别说明。循环和分支组使用成对【】，可嵌套；不配对时阅读器保留原文字，不自动修复。普通文字不会自动生成执行步骤。简单方法允许只有一个步骤；复杂方法不能用 role 的功能名称替代过程。

原有方法也显示简短执行流程；其详细分支可以按需展开。调用名称与已有 links 对应时，可从流程步骤查看目标方法；没有独立目标/关系时保留步骤文字，不制造可跳转目标。DO/DTO 等对象独立展示新增/修改/删除框，引用虚线与方法调用箭头区分，来源仍须保留词法匹配边界。


## 流程引用与画布（3.1.2）

画布根据已采集关系和方法框实际高度自动布置；支持平移、缩放、节点拖动和重新排列。几何布局不表示运行耗时。未修改方法和对象仍保留真实归属和版本信息。

每条关键调用应出现在对应 process 步骤的文字中，推荐 Class.method(参数) 或 ::method。阅读器把该引用作为连线起点，连接独立目标框；已匹配的调用不再在方法下方重复列出。第一次明确出现的调用用于锚点；这不等于运行时只调用一次，循环次数和重复调用仍用过程文字表达。

只有同名简单方法无法区分的调用，不能凭阅读顺序选目标；写出所属类或在 unknowns 中说明。无法关联到步骤的关系保留“未定位到执行步骤”入口及虚线，不能为了消除提示而删除真实关系。对象引用仍走独立对象框，非方法调用。图上手动位置是阅读偏好，不写回业务报告事实。


## 组件画布（3.2.0）

阅读器使用 React Flow 管理节点、端口、拖动、缩放和缩略图，ELK 按实际方法框尺寸及流程引用端口自动布局。依赖随本地阅读器安装和构建，无需为每份报告重新安装，不使用外部 CDN。既有报告和快照格式兼容，无需因画布升级重新分析源码。

展开分支后端口随内容更新；手动拖动后连线随节点移动。需要按新尺寸重新避让时使用“自动排列”。方法框打开完整方法，流程中的引用打开目标方法，源码继续在右侧展示。布局仅帮助阅读，不证明调用关系、执行先后、耗时或覆盖完整性；这些仍由源码证据与报告说明提供。
